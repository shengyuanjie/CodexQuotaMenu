# Codex 用量窗口定时激活设计

日期：2026-09-01  
状态：已获用户口头确认，待书面复核

## 1. 目标

在 CodexQuotaMenu 中增加一个可视化设置入口，让用户配置每天任意多个 Codex 用量窗口激活时间，并通过 Codex 官方计划任务在后台执行。

核心目标：

- 激活时间由用户自行添加、删除、启用和停用，首次打开时列表为空。
- 应用退出后，已创建的计划任务仍由 Codex 后台运行。
- 成功激活保持静默，仅失败时通知。
- 应用只读核对本机 Codex 计划任务，自动判断期望配置与实际配置是否一致。
- 应用不直接修改 Codex 的内部计划任务文件，也不使用模拟键鼠、私有接口或未公开的深链接参数。

官方文档说明计划任务应在 Codex 或 ChatGPT 对话中创建和管理，Codex CLI 当前不提供计划任务管理界面：<https://learn.chatgpt.com/docs/automations>。

## 2. 用户流程

1. 用户从状态栏菜单打开“激活时间设置…”。
2. 设置窗口首次显示空列表和“未配置激活时间”。
3. 用户添加一个或多个时间；应用在本机保存期望配置并显示“待同步”。
4. 用户点击“同步到 Codex”。
5. 应用生成一条完整对账指令、复制到剪贴板，并通过受支持的 `codex://threads/new` 入口打开 Codex。
6. 用户只需粘贴并发送一次指令。
7. 应用继续只读检查本机 Codex 计划任务；实际配置与期望配置一致后自动显示“已同步”。
8. 后续修改时间时重复同一流程。日常计划任务执行不需要打开 CodexQuotaMenu。

受官方能力限制，应用不能直接替用户提交对话或无确认地创建官方计划任务。同步按钮不得暗示已经完成创建，只能在本地检测一致后显示“已同步”。

## 3. 设置界面

新增一个独立的 AppKit 设置窗口，不扩大现有状态栏菜单的常驻信息量。

窗口包含：

- 激活时间列表，按当天时间升序排列。
- 每项的启用开关、原生时间选择器和删除按钮。
- “添加时间”按钮。
- 同步状态及必要的差异说明。
- “同步到 Codex”主按钮。

交互规则：

- 首次使用不预填任何时间。
- 时间精确到分钟。
- 相同时间不得重复添加；输入重复项时就地提示。
- “添加时间”从当前分钟开始寻找第一个未占用分钟并跨午夜回绕；一天 1,440 个分钟全部占用时显示错误且不改写存储。
- 启用项参与同步；停用项保留在本地，但不应存在对应的活动 Codex 任务。
- 保存后立即更新本地期望状态，无须额外“应用”步骤。
- 列表清空后仍允许同步；同步指令将删除所有由本工具管理的任务。

## 4. 任务所有权与固定配置

每个启用时间对应一个独立的 Codex standalone cron 任务。所有受管任务使用稳定名称：

```text
CodexQuotaMenu · HH:mm
```

只有完整名称严格匹配 `CodexQuotaMenu · HH:mm`（`HH` 为 00–23，`mm` 为 00–59）的任务属于本工具。仅共享 `CodexQuotaMenu · ` 前缀的名称（例如 `CodexQuotaMenu · backup`、`CodexQuotaMenu · 06:00 copy`）不属于本工具；同步指令必须明确保持它们不变，不得删除、修改或合并。

每个受管任务固定使用：

- 类型：standalone cron
- 周期：每天一次，带显式 `TZID`，并与每次扫描或生成指令时的系统当前 IANA 时区标识一致
- 模型：`gpt-5.6-luna`
- 推理强度：`low`
- 通知策略：仅失败时通知
- 执行环境：本机、projectless
- 提示词：仅要求完成最小激活响应，不读取文件、不调用工具、不执行其他工作

现有的 06:00 和 11:02 计划任务不由本工具接管或迁移。用户会自行删除它们；工具只创建完整名称严格匹配 `CodexQuotaMenu · HH:mm` 的新任务。

## 5. 同步指令

`SyncPromptBuilder` 根据本地启用时间生成一条完整、幂等的对账指令。指令要求 Codex：

- 列出并检查所有完整名称严格匹配 `CodexQuotaMenu · HH:mm` 的任务；可报告仅共享前缀的畸形名称，但必须保持它们不变。
- 为缺少的启用时间创建任务。
- 修正名称匹配但时间或固定配置不一致的任务。
- 删除已不在期望列表中的受管任务。
- 合并或删除重复的受管任务，使每个期望时间恰好保留一个。
- 不触碰任何完整名称不严格匹配 `CodexQuotaMenu · HH:mm` 的任务。
- 完成后简短报告实际结果。

应用不解析对话回复来判断成功。回复可能与真实持久化状态不一致，最终判断以本机只读检测到的任务配置为准。

## 6. 本地任务读取与对账

`CodexAutomationReader` 只读扫描：

```text
~/.codex/automations/*/automation.toml
```

只提取对账所需字段：版本、ID、类型、名称、状态、周期、模型、推理强度、通知策略、执行环境和目标。读取器不写入、移动或删除任何 Codex 文件。

对账结果分为：

- `unconfigured`：本地期望列表为空，且不存在受管任务。
- `synced`：每个启用时间恰好对应一个活动任务，且固定配置全部一致；不存在多余任务。
- `pending`：存在缺少、多余、重复、暂停或配置不一致的受管任务。
- `unavailable`：目录不可读、格式不支持或关键字段无法可靠解析。

差异详情应具体列出：

- 缺少的时间
- 多余的时间
- 重复的时间
- 已暂停的任务
- 配置不一致的任务

读取属于对 Codex 当前本地内部存储格式的兼容性集成，而不是公开 API。读取器必须检查 `version`，区分顶层字段与 TOML 表体，并容忍结构明确的未知字段。缺少或无法解析顶层 `name`、重复的已识别顶层键、可能遮蔽已识别键的不支持表结构、不可读文件、未知版本或其他结构歧义都返回 `unavailable`，不得猜测或误报“已同步”。顶层 `name` 可可靠解析为个人任务时，即使提示词或注释包含受管名称也应忽略。

应用启动、设置窗口获得焦点、用户点击刷新，以及打开设置窗口期间的十秒轮询都会触发异步检测。目录和文件扫描在 utility 后台任务执行，结果只在主 actor 应用，并使用单调递增代际编号阻止旧结果覆盖新结果。应用启动时必须先建立现有用量刷新及计时器，再开始自动化扫描；同一次打开/聚焦不得触发重复的即时扫描。该路径不得影响现有每 5 秒一次的用量读取语义。

## 7. 本地数据

`ActivationScheduleStore` 使用 `UserDefaults` 保存：

- 时间的小时和分钟
- 是否启用
- 稳定的本地条目 ID

不保存 Codex 登录信息、对话内容、计划任务提示词副本或账户凭据。列表写入前排序并去重，解码失败时保留可恢复错误状态，不静默覆盖为默认值。

存储读取使用 `object(forKey:)` 区分“未设置”和“键存在但不是 Data”；时间和稳定本地 ID 都必须唯一。存在加载错误时，模型拒绝所有增删改且界面禁用添加、删除、启用开关、时间选择器和同步按钮，在明确恢复功能出现前不得覆盖损坏值。

Codex 计划任务配置是实际状态，本地时间列表是期望状态。删除应用本地设置不会直接删除 Codex 任务；只有用户发送明确的同步指令后才会改变后台任务。

## 8. 架构边界

新增职责建议拆分为：

- `ActivationSchedule`：单个本地时间条目。
- `ActivationScheduleStore`：本地持久化、排序和去重。
- `CodexAutomationReader`：只读发现并解析受管任务。
- `AutomationReconciler`：计算期望状态与实际状态差异。
- `SyncPromptBuilder`：生成幂等、范围受限的同步指令。
- `ActivationScheduleWindowController`：设置窗口与交互。

`AppDelegate` 只负责菜单入口、窗口生命周期和依赖装配。现有 `CodexClient` 的用量与线程读取职责保持不变，计划任务读取不并入 app-server JSON-RPC 流程。

## 9. 错误处理

- 剪贴板写入失败：保留生成的文本并提供再次复制，不打开成功提示。
- Codex 无法打开：指令仍留在剪贴板，提示用户手动打开 Codex。
- 自动化目录不存在：若本地列表为空则为 `unconfigured`；否则为 `pending`，而不是读取失败。
- 顶层名称可靠解析为个人任务：忽略该任务，即使其他字段、提示词或注释含受管前缀。
- 顶层名称缺失/无法解析、已识别键重复、表作用域含糊或文件不可读：整体返回 `unavailable`，避免误判并生成破坏性删除建议。
- 重复任务或多余任务：只显示差异并在下一条同步指令中要求 Codex 对账，不直接删除文件。
- 系统时区变化：界面时间仍按本机当地时间表达；生成指令时明确写入当前 IANA 时区。

## 10. 非目标

本功能不负责：

- 直接编辑 `automation.toml`。
- 调用未公开的计划任务接口。
- 通过 AppleScript、辅助功能或模拟键鼠替用户提交对话。
- 证明某一次计划任务实际执行成功。
- 计算五小时窗口的真实开始时间或保证一次最小请求一定触发计费窗口。
- 接管任何完整名称不严格匹配 `CodexQuotaMenu · HH:mm` 的计划任务。

当前能够可靠验证的是任务配置是否存在、启用并符合预期。运行历史若未来出现官方稳定接口，可作为独立增强项加入。

## 11. 测试与验收

实现采用测试驱动，最低验收包括：

1. 空配置、单时间、多时间、跨午夜排序和重复时间校验正确。
2. 本地配置可以保存、重载，损坏数据不会静默覆盖。
3. 读取器正确解析当前版本的 standalone cron 任务并忽略无关任务。
4. 未知版本、缺少关键字段和疑似受管但损坏的任务返回 `unavailable`。
5. 对账正确识别缺少、多余、重复、暂停和固定配置不一致。
6. 同步指令覆盖创建、更新、删除、去重和空列表清理，并明确只操作完整名称严格匹配 `CodexQuotaMenu · HH:mm` 的任务。
7. 设置窗口首次为空；添加、删除、启停、排序和状态更新符合设计。
8. 点击同步后成功复制指令并尝试打开 Codex，但在本地检测一致前不会显示“已同步”。
9. 现有用量刷新、状态栏菜单和手机接口测试不回归。
10. Swift 测试、Release 构建、签名验证和已安装应用 `--check` 通过。
11. 使用测试目录模拟 Codex 自动化文件完成端到端对账验证；不得在自动化测试中写入真实 `~/.codex/automations`。

## 12. 交付边界

- 更新本地 Mac 应用、相关测试及中英文使用说明。
- 不删除或修改当前 06:00、11:02 以及其他现有计划任务。
- 不创建 PR、不推送、不打标签、不发布 Release，除非用户另行明确授权。
- 真实计划任务的创建仍需用户在 Codex 中发送一次生成的同步指令；不能仅凭复制成功宣称后台任务已经创建。
