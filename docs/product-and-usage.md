# Codex 用量：产品功能与使用说明

[English](product-and-usage.en.md) | 简体中文

适用版本：v1.5.0

适用系统：macOS 14 或更高版本

支持架构：Apple Silicon（`arm64`）与 Intel（`x86_64`）

## 一、产品简介

Codex 用量是一款原生 macOS 菜单栏工具，用于快速查看 Codex 剩余用量、重置倒计时和当前任务状态。

应用常驻屏幕顶部菜单栏，不显示主窗口或 Dock 图标，也不显示已经完成的任务数量。它使用本机现有的 Codex 登录状态，不要求用户向本项目提供账号令牌。

## 二、主要功能

- 显示 Codex 当前剩余用量百分比；
- 显示用量窗口的具体重置时间和剩余倒计时；
- 同时展示 Codex 返回的各个用量窗口和当前方案类型；
- 使用 `▶` 显示正在正常执行的任务数量；
- 使用 `⏸` 显示正在等待批准、选择、输入、上传或回复的任务数量；
- 在下拉菜单中列出最近的正常执行和等待操作任务；
- 支持跟随系统、简体中文和 English，并可即时切换；
- 查询失败时保留菜单栏中的上次成功结果；
- 支持手动立即刷新和登录 macOS 时自动启动；
- 不包含广告、遥测、用户分析或第三方运行时依赖。

## 三、菜单栏界面

菜单栏内容类似：

```text
Codex 90% · 4时25分 · ▶ 1 ｜ ⏸ 0
```

英文界面会显示为类似：

```text
Codex 90% · 4h 25m · ▶ 1 | ⏸ 0
```

| 显示内容 | 含义 |
|---|---|
| `Codex 90%` | 当前最短用量窗口的剩余比例 |
| `4时25分` | 距离该窗口重置的时间 |
| `▶ 1` | 正在正常执行的任务数量 |
| `⏸ 0` | 正在等待用户操作的任务数量 |

如果账号同时返回多个用量窗口，菜单栏优先显示周期最短的窗口。点击菜单栏项目后，可以查看：

- 每个用量窗口的名称和剩余比例；
- 每个用量窗口的具体重置日期、时间和倒计时；
- 当前 Codex 方案类型；
- 正常执行和等待操作的任务数量；
- 每类任务最近五项的标题；
- 异常任务数量（存在时显示）；
- 最近一次成功更新时间；
- “立即刷新”和“退出”操作。

应用每次最多查询 Codex 最近更新的 50 个任务。任务标题超过 36 个字符时会在菜单中缩短显示；这不会修改 Codex 中的原始任务名称。

## 四、任务状态说明

### `▶` 正常执行

以下情况通常会计入正常执行：

- Codex 正在推理、生成内容或调用工具；
- 任务日志仍在持续写入，且没有等待用户操作的标记；
- 用户完成批准、选择或输入后，任务已经继续执行。

### `⏸` 等待用户操作

以下情况通常会计入等待：

- 等待高权限操作批准；
- 计划模式正在等待用户选择；
- 等待表单、选项或其他手动输入；
- 当前完整回复明确要求用户提供资料、选择方案、上传文件、确认或回复；
- 后续工作明确依赖用户先完成某项操作。

状态判断会优先采用 Codex 提供的运行标志和待处理工具调用。任务已经结束、但回复仍明确要求用户继续操作时，应用会结合本轮完整回复进行本地判断。

普通功能说明、引用示例、代码块、可选建议、否定表达和已经完成的动作会尽量排除，以降低误判。自然语言表达非常多样，`⏸` 仍可能出现少量误判或漏判。

### 不显示已完成任务

已完成任务不会出现在菜单栏数量或任务列表中。应用内部仍会识别完成标记，用于及时移除 `▶` 状态，避免任务结束后继续显示为正在执行。

### 异常任务

Codex 明确返回系统错误状态时，下拉菜单会显示 `⚠ 异常` 数量。异常数量不会占用菜单栏上的 `▶` 或 `⏸` 数字。

## 五、刷新机制

应用启动后会：

1. 查找本机可信的 Codex 可执行程序；
2. 启动本机 `codex app-server --stdio` 子进程；
3. 复用现有 Codex 登录状态建立持续连接；
4. 查询用量和最近任务；
5. 每 5 秒自动刷新一次。

这里的“实时”是指持续连接配合高频自动刷新，并不是服务端推送。正常情况下，状态变化会在下一次刷新后显示；Codex 响应时间也会影响实际延迟。

点击菜单中的“立即刷新”，可以不等待下一次自动刷新。为避免请求重叠，已有刷新尚未结束时不会再同时启动第二次刷新。

如果刷新失败：

- 已经取得过数据时，菜单栏保留上次成功结果，并在下拉菜单提示失败原因；
- 尚未取得数据时，菜单栏显示 `Codex --`；
- 后续自动刷新仍会继续尝试重新连接。

## 六、系统要求与版本选择

- macOS 14 或更高版本；
- Apple Silicon 或 Intel 64 位 Mac；
- 已安装并登录以下任一产品：
  - Codex 桌面版；
  - ChatGPT 桌面版内置 Codex；
  - Codex CLI。

GitHub Release 分别提供两套原生安装包：

| 文件名标识 | 适用设备 |
|---|---|
| `macOS-arm64` | Apple M 系列芯片 |
| `macOS-x86_64` | Intel 处理器 |

两套安装包功能相同，不需要同时下载。它们不是通用二进制，请务必选择与处理器匹配的版本。

为避免 GitHub 改写非 ASCII 发布资源名称，安装包文件名使用英文 `CodexQuotaMenu`；解压后的应用名称仍为 `Codex用量.app`。

### 查看 Mac 处理器类型

方法一：打开“苹果菜单 → 关于本机”。

- 显示 Apple M 系列芯片：下载 `arm64`；
- 显示 Intel 处理器：下载 `x86_64`。

方法二：在终端运行：

```sh
uname -m
```

输出 `arm64` 时选择 Apple Silicon 版本，输出 `x86_64` 时选择 Intel 版本。

## 七、下载安装

1. 打开项目的 GitHub Releases 页面；
2. 下载与处理器匹配的 ZIP 安装包；
3. 同时下载同名的 `.sha256` 校验文件；
4. 校验文件完整性；
5. 解压 ZIP；
6. 将 `Codex用量.app` 拖入“应用程序”文件夹。

请勿直接从解压目录或“下载”文件夹长期运行应用，否则移动或清理下载文件后应用会消失。拖入“应用程序”后，原 ZIP 可以保留作备份，也可以在确认安装正常后删除；以后换电脑时可重新从官方 GitHub Release 下载对应架构的版本。

### 校验下载文件

在终端进入安装包所在目录，然后运行：

Apple Silicon：

```sh
shasum -a 256 -c CodexQuotaMenu-v1.5.0-macOS-arm64.zip.sha256
```

Intel：

```sh
shasum -a 256 -c CodexQuotaMenu-v1.5.0-macOS-x86_64.zip.sha256
```

显示 `OK` 表示 ZIP 与发布时生成的校验值一致。校验只能证明文件与对应校验清单匹配，因此 ZIP 和 `.sha256` 都应从本项目的同一个 GitHub Release 下载。

## 八、首次启动

项目目前没有 Apple Developer 证书。安装包启用了 Hardened Runtime 并采用 ad-hoc 签名，但没有经过 Apple 公证。

首次双击时，macOS 可能提示无法验证开发者或阻止打开。确认安装包来自本项目 GitHub Release，且 SHA-256 校验通过后，可以：

1. 在 Finder 中打开“应用程序”；
2. 找到 `Codex用量.app`；
3. 右键应用并选择“打开”；
4. 在系统提示中再次选择“打开”。

不要关闭 macOS 系统安全机制，也不要执行来源不明的终端命令解除安全限制。

启动成功后查看屏幕顶部菜单栏。应用不会打开普通窗口，也不会出现在 Dock 中，这是正常行为。

## 九、日常使用

### 查看详细信息

点击菜单栏中的 Codex 用量内容，即可展开用量窗口、任务状态和更新时间。

### 手动刷新

选择“立即刷新”，或在菜单打开时按 `R`。

### 切换界面语言

选择“语言”，然后选择：

- **跟随系统**：系统首选语言为中文时显示简体中文，其他语言默认显示 English；
- **简体中文**：始终显示中文界面；
- **English**：始终显示英文界面。

切换立即生效，不需要退出或重新启动。任务标题由 Codex 原样提供，不会被自动翻译。

### 退出

选择“退出”，或在菜单打开时按 `Q`。退出后，应用会停止查询用量和读取任务状态。

## 十、登录时自动启动

1. 打开“系统设置”；
2. 进入“通用 → 登录项”；
3. 在“登录时打开”区域点击“+”；
4. 选择“应用程序”中的 `Codex用量.app`。

如果以后移动或重新安装了应用，请检查登录项是否仍指向“应用程序”文件夹中的当前版本。

## 十一、隐私与安全边界

应用会在本机处理：

- Codex 用量、重置时间和方案类型；
- 最近任务的标识、标题、更新时间和运行状态；
- Codex 返回的本机会话日志路径；
- 相关会话日志末尾最多 512KB。
- 用户选择的界面语言。

日志片段用于识别最近一次用户消息、任务完成标记、待批准操作，以及当前完整回复是否仍在等待用户操作。片段可能包含任务标题、工具调用元数据和当前轮回复。

这些数据：

- 只在设备内存中处理；
- 不写入本项目自己的数据库；
- 不保存、复制或上传会话内容；
- 不读取或保存账号令牌、密码或 API Key；
- 不用于广告、遥测、崩溃上传或用户分析。

界面语言是应用唯一主动持久化的设置，使用 macOS `UserDefaults` 保存在本机，取值仅为跟随系统、简体中文或 English，不包含任务内容或身份信息。

应用本身没有实现网络上传功能，但它启动的 Codex 子进程可能按照 Codex 产品本身的正常方式连接 OpenAI 服务。

由于核心功能需要启动本机 Codex 子进程并读取 Codex 返回路径对应的会话日志，应用没有启用 App Sandbox。应用不请求相机、麦克风、通讯录、日历、位置、照片或辅助功能权限。

详细说明见 [隐私说明](../PRIVACY.md)，安全问题的报告方式见 [安全策略](../SECURITY.md)。

## 十二、常见问题

### 启动后没有窗口

这是菜单栏应用。请查看屏幕顶部菜单栏；应用没有主窗口或 Dock 图标。

### 菜单栏图标或文字没有出现

- 检查菜单栏右侧是否空间不足；
- 暂时退出其他占用菜单栏的应用；
- 在“活动监视器”中确认 `Codex用量` 是否正在运行；
- 退出后从“应用程序”重新启动。

### 一直显示“读取中…”或 `Codex --`

- 确认 Codex 或 ChatGPT 桌面版已经安装并登录；
- 先打开 Codex 并确认能够正常使用；
- 点击“立即刷新”或退出后重新启动；
- 检查本机 Codex 是否安装在应用支持的常见位置。

### 显示“未找到 Codex”

应用依次检查：

- `/Applications/Codex.app/Contents/Resources/codex`
- `/Applications/ChatGPT.app/Contents/Resources/codex`
- `~/.local/bin/codex`
- `/opt/homebrew/bin/codex`
- `/usr/local/bin/codex`

高级用户可以通过启动环境中的 `CODEX_CLI_PATH` 指定其他位置：

```sh
CODEX_CLI_PATH=/完整路径/codex
```

该路径必须指向可信且具有执行权限的 Codex 文件。通过 Finder 启动的应用通常不会继承终端当前会话中的临时环境变量。

### 用量或任务状态没有立即变化

应用每 5 秒自动刷新一次，Codex 本机接口的响应时间也会带来少量延迟。可以点击“立即刷新”。

### 没有任务却显示 `▶ 1`

任务正常完成后，Codex 日志中的完成标记会将其移出运行状态。若任务异常中断且没有完成标记，应用会参考日志更新时间；超过 30 分钟没有更新的未完成日志不会继续计入运行中。

如果状态仍未变化，可以：

1. 点击“立即刷新”；
2. 等待本轮 Codex 状态写入完成；
3. 退出并重新启动应用。

### `⏸` 与实际情况不一致

等待状态优先使用 Codex 的运行标志和待处理工具调用；对于已结束但仍要求回复的任务，会分析本轮完整回复。自然语言存在歧义，因此仍可能出现少量误判或漏判。

用户完成批准、选择或回复后，状态通常会在下一次刷新时恢复。若没有恢复，可点击“立即刷新”。

### 只显示部分任务标题

应用每次最多查询最近更新的 50 个任务，下拉菜单中每类最多列出五项。菜单栏数字显示本次查询结果中识别到的总数。

### 安装后提示无法验证开发者

这是没有 Apple Developer 证书和公证导致的预期提示。先确认文件来自本项目 GitHub Release，并通过 SHA-256 校验，再使用 Finder 右键“打开”。

### 更新后仍像旧版本

1. 从菜单退出正在运行的旧版本；
2. 将新版应用复制到“应用程序”并确认替换；
3. 从“应用程序”重新启动；
4. 如设置了登录项，确认登录项指向新版应用。

## 十三、退出与卸载

### 临时退出

点击菜单栏项目并选择“退出”。这会停止应用及其启动的本机 Codex 查询子进程。

### 完全卸载

1. 先退出应用；
2. 从“系统设置 → 通用 → 登录项”中移除；
3. 将“应用程序”中的 `Codex用量.app` 移到废纸篓。

应用不创建自己的数据库或缓存目录。卸载本工具不会删除 Codex 应用、Codex 登录状态或原有任务记录。

如需同时移除已保存的界面语言偏好，可在终端运行：

```sh
defaults delete com.local.codexquotamenu
```

## 十四、已知边界

- 状态并非服务端推送，最长通常需要等待下一次 5 秒刷新；
- 任务状态依赖本机 Codex 接口和会话日志格式，Codex 后续更新可能影响兼容性；
- `⏸` 的自然语言判断可能出现少量误判或漏判；
- 菜单栏只显示最短用量窗口，其他窗口需点击后查看；
- 应用仅提供信息展示，不会修改用量、重置时间或 Codex 任务；
- 当前没有 Apple Developer 证书和公证，首次启动体验不如已公证应用；
- 本项目仅支持 macOS，不提供 Windows、Linux、iPhone 或 iPad 版本。

## 十五、从源码构建

需要安装 Xcode Command Line Tools。在项目根目录运行：

```sh
./build-app.sh
```

脚本会为当前 Mac 的原生架构创建 Release 应用、移除调试符号和编译机绝对路径、加入应用图标、启用 Hardened Runtime、执行 ad-hoc 签名并验证签名。

公共 Release 由 GitHub Actions 分别在 Apple Silicon 和 Intel Runner 上构建。发布流程会检查：

- 两种架构是否均已生成；
- 文件名和版本标签是否一致；
- ZIP 和 SHA-256 是否完整；
- 安装包中的实际二进制架构是否正确；
- 签名、动态依赖、用户绝对路径和常见凭据格式是否通过审计。

任一架构缺失或验证失败时，不会创建 Release。
