# Codex 用量：产品功能与使用说明

[English](product-and-usage.en.md) | 简体中文

适用版本：v1.6.2

适用系统：macOS 14 或更高版本

支持架构：Apple Silicon（`arm64`）与 Intel（`x86_64`）

## 一、产品简介

Codex 用量是一款原生 macOS 菜单栏工具，用于快速查看 Codex 剩余用量、重置倒计时、全局额外重置预测和当前任务状态。它还可向 iPhone Scriptable 锁屏小组件提供默认关闭的只读数据。

应用常驻屏幕顶部菜单栏，不显示主窗口或 Dock 图标，也不显示已经完成的任务数量。它使用本机现有的 Codex 登录状态，不要求用户向本项目提供账号令牌。

菜单栏采用纯文字显示，不在 `Codex` 前放置额外图标，以保持界面简洁并节省菜单栏空间。

## 二、主要功能

- 显示 Codex 当前剩余用量百分比；
- 显示用量窗口的具体重置时间和剩余倒计时；
- 同时展示 Codex 返回的各个用量窗口和当前方案类型；
- 使用 `▶` 显示当前仍处于活动状态的任务数量；
- 使用 `↻48h` 显示 Codex Reset Monitor 的未来48小时全局额外重置概率；
- 在下拉菜单中列出最近的活动任务；
- 支持跟随系统、简体中文和 English，并可即时切换；
- 查询失败时保留菜单栏中的上次成功结果；
- 支持手动立即刷新和登录 macOS 时自动启动；
- 支持通过一次确认将每日激活时间对账到 Codex 官方计划任务；
- 可选提供受 Keychain 令牌保护的手机只读接口；
- 不包含广告、遥测、用户分析或第三方运行时依赖。

## 三、菜单栏界面

菜单栏内容类似：

```text
Codex 90% · 4时25分 · ↻48h 82% · ▶ 1
```

英文界面会显示为类似：

```text
Codex 90% · 4h 25m · ↻48h 82% · ▶ 1
```

| 显示内容 | 含义 |
|---|---|
| `Codex 90%` | 当前最短用量窗口的剩余比例 |
| `4时25分` | 距离该窗口重置的时间 |
| `↻48h 82%` | 未来48小时发生全局额外重置的概率 |
| `▶ 1` | 当前仍处于活动状态的任务数量 |

如果账号同时返回多个用量窗口，菜单栏优先显示周期最短的窗口。点击菜单栏项目后，可以查看：

- 每个用量窗口的名称和剩余比例；
- 每个用量窗口的具体重置日期、时间和倒计时；
- 当前 Codex 方案类型；
- 活动任务数量；
- 最近五项活动任务的标题；
- 异常任务数量（存在时显示）；
- 最近一次成功更新时间；
- 未来48小时概率、预测状态、来源和更新时间；
- “手机小组件”只读接口控制；
- “立即刷新”和“退出”操作。

应用每次最多查询 Codex 最近更新的 50 个任务。任务标题超过 36 个字符时会在菜单中缩短显示；这不会修改 Codex 中的原始任务名称。

## 四、任务状态说明

### `▶` 活动任务

以下情况会计入活动任务：

- Codex 正在推理、生成内容或调用工具；
- Codex 将任务标记为 active，包括 active 状态下的附加标志；
- 结构化日志中最新的生命周期事件是任务开始，且日志在最近 30 分钟内仍有更新；
- 生命周期标志超出读取范围时，日志末尾仍存在近期活动记录。

应用不再区分“正在执行”和“等待用户操作”，也不会读取回复文字来推断用户是否需要批准、选择、输入、上传或回复。这样可以避免自然语言判断带来的 `⏸` 误判。

### 不显示已完成任务

已完成任务不会出现在菜单栏数量或任务列表中。应用内部仍会识别完成标记，用于及时移除 `▶` 状态，避免任务结束后继续显示为正在执行。

### 异常任务

Codex 明确返回系统错误状态时，下拉菜单会显示 `⚠ 异常` 数量。异常数量不会占用菜单栏上的 `▶` 数字。

## 五、刷新机制

应用启动后会：

1. 查找本机可信的 Codex 可执行程序；
2. 启动本机 `codex app-server --stdio` 子进程；
3. 复用现有 Codex 登录状态建立持续连接；
4. 查询用量和最近任务；
5. 每 5 秒自动刷新一次。

这里的“实时”是指持续连接配合高频自动刷新，并不是服务端推送。正常情况下，状态变化会在下一次刷新后显示；Codex 响应时间也会影响实际延迟。

点击菜单中的“立即刷新”，可以不等待下一次自动刷新。为避免请求重叠，已有刷新尚未结束时不会再同时启动第二次刷新。

如果刷新失败：

- 已经取得过数据时，菜单栏保留上次成功结果，并在下拉菜单提示失败原因；
- 尚未取得数据时，菜单栏显示 `Codex --`；
- 后续自动刷新仍会继续尝试重新连接。

### 全局额外重置预测

- `codexreset.org/api/monitor-summary` 是菜单栏和手机 `↻48h` 概率的唯一来源；
- 每5分钟请求一次，失败不会阻塞个人用量和任务刷新；
- 预测15分钟内视为实时，之后显示为缓存，超过2小时则隐藏。

## 六、系统要求与版本选择

- macOS 14 或更高版本；
- Apple Silicon 或 Intel 64 位 Mac；
- 已安装并登录以下任一产品：
  - Codex 桌面版；
  - ChatGPT 桌面版内置 Codex；
  - Codex CLI。

GitHub Release 分别提供两套原生安装包：

| 文件名标识 | 适用设备 |
|---|---|
| `macOS-arm64` | Apple M 系列芯片 |
| `macOS-x86_64` | Intel 处理器 |

两套安装包功能相同，不需要同时下载。它们不是通用二进制，请务必选择与处理器匹配的版本。

为避免 GitHub 改写非 ASCII 发布资源名称，安装包文件名使用英文 `CodexQuotaMenu`；解压后的应用名称仍为 `Codex用量.app`。

### 查看 Mac 处理器类型

方法一：打开“苹果菜单 → 关于本机”。

- 显示 Apple M 系列芯片：下载 `arm64`；
- 显示 Intel 处理器：下载 `x86_64`。

方法二：在终端运行：

```sh
uname -m
```

输出 `arm64` 时选择 Apple Silicon 版本，输出 `x86_64` 时选择 Intel 版本。

## 七、下载安装

1. 打开项目的 GitHub Releases 页面；
2. 下载与处理器匹配的 ZIP 安装包；
3. 同时下载同名的 `.sha256` 校验文件；
4. 校验文件完整性；
5. 解压 ZIP；
6. 将 `Codex用量.app` 拖入“应用程序”文件夹。

请勿直接从解压目录或“下载”文件夹长期运行应用，否则移动或清理下载文件后应用会消失。拖入“应用程序”后，原 ZIP 可以保留作备份，也可以在确认安装正常后删除；以后换电脑时可重新从官方 GitHub Release 下载对应架构的版本。

### 校验下载文件

在终端进入安装包所在目录，然后运行：

Apple Silicon：

以下文件名用于校验 v1.6.2 的正式发布资产：

```sh
shasum -a 256 -c CodexQuotaMenu-v1.6.2-macOS-arm64.zip.sha256
```

Intel：

```sh
shasum -a 256 -c CodexQuotaMenu-v1.6.2-macOS-x86_64.zip.sha256
```

显示 `OK` 表示 ZIP 与发布时生成的校验值一致。校验只能证明文件与对应校验清单匹配，因此 ZIP 和 `.sha256` 都应从本项目的同一个 GitHub Release 下载。

## 八、首次启动

项目目前没有 Apple Developer 证书。安装包启用了 Hardened Runtime 并采用 ad-hoc 签名，但没有经过 Apple 公证。

首次双击时，macOS 可能提示无法验证开发者或阻止打开。确认安装包来自本项目 GitHub Release，且 SHA-256 校验通过后，可以：

1. 在 Finder 中打开“应用程序”；
2. 找到 `Codex用量.app`；
3. 右键应用并选择“打开”；
4. 在系统提示中再次选择“打开”。

不要关闭 macOS 系统安全机制，也不要执行来源不明的终端命令解除安全限制。

启动成功后查看屏幕顶部菜单栏。应用不会打开普通窗口，也不会出现在 Dock 中，这是正常行为。

## 九、日常使用

### 查看详细信息

点击菜单栏中的 Codex 用量内容，即可展开用量窗口、任务状态和更新时间。

### 手动刷新

选择“立即刷新”，或在菜单打开时按 `R`。

### 切换界面语言

选择“语言”，然后选择：

- **跟随系统**：系统首选语言为中文时显示简体中文，其他语言默认显示 English；
- **简体中文**：始终显示中文界面；
- **English**：始终显示英文界面。

切换立即生效，不需要退出或重新启动。任务标题由 Codex 原样提供，不会被自动翻译。

### 每日激活时间

选择“激活时间设置…”，添加每天需要的时间，然后点击“同步到 Codex”。首次打开时，时间列表为空。应用会复制一条完整的对账指令并打开新的 Codex 对话；用户仍需将指令粘贴并发送一次，Codex 才会创建或修正官方计划任务。

应用只管理名称严格为 `CodexQuotaMenu · HH:mm` 格式的受管任务，不会接管已有的无此前缀任务。若时间列表为空，生成的同步指令只清理此前缀的受管任务。

同步按钮本身不会显示“已同步”。发送指令后，窗口通过本机只读对账重新检查配置；只有本地设置和受管任务配置完全一致时才显示“已同步”。本地对账不能证明某次后台运行成功。只有修改时间后才需再次同步；退出 CodexQuotaMenu 不会停止或删除已创建的官方后台任务。成功的计划任务运行保持静默，失败时由 Codex 按任务通知策略提示。

### iPhone Scriptable 锁屏小组件

1. 选择“手机小组件 → 启用只读接口”；
2. 分别复制小组件地址和访问令牌；菜单不会直接显示完整令牌；
3. 按 [`mobile/README.md`](../mobile/README.md) 将脚本导入 Scriptable 并在前台完成配置测试；
4. 在锁屏添加 Scriptable 横向矩形小组件并指定该脚本。

普通 HTTP 仅用于可信局域网或用户已有的加密 Shadowrocket/VPN 回家链路，不得映射到公网。经回家链路访问时建议为 Mac 保留固定局域网 IP，因为 `.local` 不一定能解析。脚本建议 iOS 最早在 5 分钟后刷新，但系统不保证准时执行。

### 退出

选择“退出”，或在菜单打开时按 `Q`。退出后，应用会停止查询用量和读取任务状态。

## 十、登录时自动启动

1. 打开“系统设置”；
2. 进入“通用 → 登录项”；
3. 在“登录时打开”区域点击“+”；
4. 选择“应用程序”中的 `Codex用量.app`。

如果以后移动或重新安装了应用，请检查登录项是否仍指向“应用程序”文件夹中的当前版本。

## 十一、隐私与安全边界

应用会在本机处理：

- Codex 用量、重置时间和方案类型；
- 最近任务的标识、标题、更新时间和运行状态；
- Codex 返回的本机会话日志路径；
- 相关会话日志末尾最多 512KB；
- 用户选择的界面语言；
- 公开预测接口返回的未来48小时概率、状态和时间；
- 用户是否启用手机接口，以及手机接口访问令牌。

为对账每日激活时间，应用只读扫描 `~/.codex/automations/*/automation.toml`，仅提取受管任务名称、状态和对账所需配置字段。应用不会写入这些文件、不读取计划任务运行对话，也不上传计划任务配置。本地检测只能确认配置一致，不能证明某次后台运行成功。

日志片段只用于识别任务开始、用户消息、任务完成等结构化生命周期事件，以及近期是否仍有任务活动。应用不再分析回复文字或工具调用内容来判断用户意图。

个人 Codex 会话内容和任务明细：

- 只在设备内存中处理；
- 不写入本项目自己的数据库；
- 不保存、复制或上传会话内容；
- 不读取或保存账号令牌、密码或 API Key；
- 不用于广告、遥测、崩溃上传或用户分析；
- 不向预测站点发送个人余量、任务、身份、会话或 Codex 凭据。

macOS `UserDefaults` 保存界面语言、手机接口开关和不含个人数据的公开预测缓存；缓存超过两小时不再显示。32 字节随机手机令牌只保存在 macOS Keychain。手机接口响应不含任务标题、路径或对话内容。Scriptable 把地址和令牌存入自己的 Keychain，本地文件只缓存非敏感 JSON 和接收时间。

应用只额外请求已披露的 `codexreset.org` 公开预测 GET，不上传个人数据。它启动的 Codex 子进程可能按照 Codex 产品本身的正常方式连接 OpenAI 服务。

由于核心功能需要启动本机 Codex 子进程并读取 Codex 返回路径对应的会话日志，应用没有启用 App Sandbox。应用不请求相机、麦克风、通讯录、日历、位置、照片或辅助功能权限。

详细说明见 [隐私说明](../PRIVACY.md)，安全问题的报告方式见 [安全策略](../SECURITY.md)。

## 十二、常见问题

### 启动后没有窗口

这是菜单栏应用。请查看屏幕顶部菜单栏；应用没有主窗口或 Dock 图标。

### 菜单栏图标或文字没有出现

- 检查菜单栏右侧是否空间不足；
- 暂时退出其他占用菜单栏的应用；
- 在“活动监视器”中确认 `Codex用量` 是否正在运行；
- 退出后从“应用程序”重新启动。

### 一直显示“读取中…”或 `Codex --`

- 确认 Codex 或 ChatGPT 桌面版已经安装并登录；
- 先打开 Codex 并确认能够正常使用；
- 点击“立即刷新”或退出后重新启动；
- 检查本机 Codex 是否安装在应用支持的常见位置。

### 显示“未找到 Codex”

应用依次检查：

- `/Applications/Codex.app/Contents/Resources/codex`
- `/Applications/ChatGPT.app/Contents/Resources/codex`
- `~/.local/bin/codex`
- `/opt/homebrew/bin/codex`
- `/usr/local/bin/codex`

高级用户可以通过启动环境中的 `CODEX_CLI_PATH` 指定其他位置：

```sh
CODEX_CLI_PATH=/完整路径/codex
```

该路径必须指向可信且具有执行权限的 Codex 文件。通过 Finder 启动的应用通常不会继承终端当前会话中的临时环境变量。

### 用量或任务状态没有立即变化

应用每 5 秒自动刷新一次，Codex 本机接口的响应时间也会带来少量延迟。可以点击“立即刷新”。

### 没有任务却显示 `▶ 1`

任务正常完成后，Codex 日志中的完成标记会将其移出运行状态。若任务异常中断且没有完成标记，应用会参考日志更新时间；超过 30 分钟没有更新的未完成日志不会继续计入运行中。

如果状态仍未变化，可以：

1. 点击“立即刷新”；
2. 等待本轮 Codex 状态写入完成；
3. 退出并重新启动应用。

### 只显示部分任务标题

应用每次最多查询最近更新的 50 个任务，下拉菜单中最多列出五项活动任务。菜单栏数字显示本次查询结果中识别到的活动任务总数。

### 安装后提示无法验证开发者

这是没有 Apple Developer 证书和公证导致的预期提示。先确认文件来自本项目 GitHub Release，并通过 SHA-256 校验，再使用 Finder 右键“打开”。

### 更新后仍像旧版本

1. 从菜单退出正在运行的旧版本；
2. 将新版应用复制到“应用程序”并确认替换；
3. 从“应用程序”重新启动；
4. 如设置了登录项，确认登录项指向新版应用。

## 十三、退出与卸载

### 临时退出

点击菜单栏项目并选择“退出”。这会停止应用及其启动的本机 Codex 查询子进程。

### 完全卸载

1. 先退出应用；
2. 从“系统设置 → 通用 → 登录项”中移除；
3. 将“应用程序”中的 `Codex用量.app` 移到废纸篓。

应用不创建用户数据库或独立缓存目录，但会在 `UserDefaults` 保存公开预测缓存和开关，在 Keychain 保存手机令牌。卸载本工具不会删除 Codex 应用、Codex 登录状态或原有任务记录。

如需同时移除已保存的界面语言、手机接口开关和公开预测缓存，可在终端运行：

```sh
defaults delete com.local.codexquotamenu
```

如需连同手机令牌一起移除，请在“钥匙串访问”中搜索并删除服务 `com.local.codexquotamenu.widget`。Scriptable 的 Keychain 项和非敏感缓存需要在 iPhone 上另行移除。

## 十四、已知边界

- 状态并非服务端推送，最长通常需要等待下一次 5 秒刷新；
- 任务状态依赖本机 Codex 接口和会话日志格式，Codex 后续更新可能影响兼容性；
- 应用不区分活动任务是在实际执行，还是正在等待用户操作；
- 菜单栏只显示最短用量窗口，其他窗口需点击后查看；
- 全局额外重置概率来自公开社区预测，只表示不确定性估计，不保证一定发生；
- 应用仅提供信息展示，不会修改用量、重置时间或 Codex 任务；
- 当前没有 Apple Developer 证书和公证，首次启动体验不如已公证应用；
- 本项目核心应用仅支持 macOS；iPhone 端为 Scriptable 脚本，不是独立原生 App，后台刷新时间由 iOS 决定。

## 十五、从源码构建

需要安装 Xcode Command Line Tools。在项目根目录运行：

```sh
./build-app.sh
```

脚本会为当前 Mac 的原生架构创建 Release 应用、移除调试符号和编译机绝对路径、加入应用图标、启用 Hardened Runtime、执行 ad-hoc 签名并验证签名。

公共 Release 由 GitHub Actions 分别在 Apple Silicon 和 Intel Runner 上构建。发布流程会检查：

- 两种架构是否均已生成；
- 文件名和版本标签是否一致；
- ZIP 和 SHA-256 是否完整；
