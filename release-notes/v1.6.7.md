## 中文

### 本版本改进

- 每日激活改为由 CodexQuotaMenu 管理的用户级 macOS LaunchAgent。
- 每个启用时间调用官方 `codex exec --ephemeral`，不把激活会话持久化为 Codex 最近任务对话。
- 调度文件使用 `~/Library/LaunchAgents/com.local.codexquotamenu.activation.HHMM.plist`，并通过 `launchctl` 校验实际加载状态。
- 首次迁移时，只有完整名称严格匹配 `CodexQuotaMenu · HH:mm` 的旧版自动化会在新 LaunchAgent 验证成功后移除；其他自动化和共享前缀文件保持不变。
- Mac 从睡眠唤醒后，macOS 可能将错过的日历触发合并为一次补执行；应用不会自行追赶多次。
- 后台激活的标准输出和标准错误写入 `/dev/null`，单次结果不持久化，当前成功和失败均保持静默；“已同步”只表示配置与加载状态一致。
- `↻48h` 预测源改为独立社区服务 `https://willcodexreset.com/api/reset-radar`；它与 OpenAI 无隶属或官方认可关系，预测不是官方计划或保证。
- 每次最多读取响应前缀 64 KiB，只保留响应代码、48小时概率与来源更新时间摘要，不保留或缓存 `events`；摘要使用 `globalReset.willCodexResetForecast.v3` 键。
- 详情中的预测更新时间取自来源 `data.updatedAt`，本机获取时间单独用于新鲜度判断。概率在一轮低位后首次达到或超过 50% 时开始鼓励提示，完成重置后需先降至 50% 以下再重新越过阈值才会再次提示。
- 已导入旧版 `CodexQuotaWidget.js` 的 Scriptable 用户需要手动替换或重新导入脚本；iOS 不会自动更新已保存的脚本。

## English

### Improvements

- Daily activation is now managed by user-level macOS LaunchAgents owned by CodexQuotaMenu.
- Each enabled time invokes the official `codex exec --ephemeral` command without persisting the activation session as a recent Codex task conversation.
- Scheduler files live at `~/Library/LaunchAgents/com.local.codexquotamenu.activation.HHMM.plist`, and actual loaded state is checked through `launchctl`.
- On first migration, only legacy automations with the exact complete name `CodexQuotaMenu · HH:mm` are removed after the new LaunchAgents verify successfully; unrelated automations and prefix-sharing files remain untouched.
- After sleep, macOS may coalesce a missed calendar trigger into one catch-up run; the app does not perform additional catch-up runs.
- Activation standard output and error go to `/dev/null`; individual results are not persisted, and both success and failure are currently silent. **Synced** covers configuration and loaded state only.
- `↻48h` now uses the independent community endpoint `https://willcodexreset.com/api/reset-radar`. It is not affiliated with or endorsed by OpenAI, and its forecast is not an official schedule or guarantee.
- Each response is limited to a 64 KiB prefix. The app retains only the response code, 48-hour probability, and source update time summary, never `events`, under cache key `globalReset.willCodexResetForecast.v3`.
- The displayed forecast time comes from source field `data.updatedAt`; local fetch time separately determines freshness. Encouragement starts on the first crossing to 50% or higher in a low-to-high cycle, and after a completed reset it cannot start again until probability drops below 50% and crosses the threshold again.
- Existing Scriptable users must manually replace or re-import `CodexQuotaWidget.js`; iOS does not automatically update a saved script.
