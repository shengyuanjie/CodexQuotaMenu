# v1.8.0 — 定时发送消息 / Scheduled Messages

## 中文

- 新增“定时发送消息…”：在指定日期时间，向指定的已有 Codex 任务发送一次消息，并选择本次使用的模型及推理强度。
- 使用 macOS 用户级 LaunchAgent；不创建 Codex 内置定时任务，不修改全局默认模型或每日激活时间。
- 任务菜单直接绑定任务 ID，同名条目显示 ID 尾部，避免选择与投递目标错配。
- 桌面端持有的任务通过现有会话投递；任务正在运行时等待空闲。没有桌面端持有者时使用 CLI。
- 支持较大的任务状态快照，并核验目标任务和本次回合完成状态；结果不明确时不自动重发。
- 桌面端路径不再先访问项目目录；CLI 路径在安排与执行时检查目录权限，区分权限拒绝、目录不存在和投递未核验。
- 发送时间默认显示当前时间，新增加减 1 分钟、10 分钟、1 小时、1 天按钮。
- 修复消息输入框 Command+V；支持复制、剪切、全选、撤销及重做。
- 修复后台服务列表无法解析负数退出状态的问题。

### 安装与使用

- 同时提供 Apple Silicon（arm64）和 Intel（x86_64）ZIP 及 SHA-256 校验文件；要求 macOS 14+。
- Build 33，启用 Hardened Runtime，使用 ad-hoc 签名，未经 Apple 公证。
- 桌面端投递依赖本机 Codex 会话接口；不兼容或连接失败时会显示失败原因。
- 消息正文在本机权限受限的记录中保存，直至用户移除。仅在用户安排的时间交给 Codex 处理。
- 睡眠或重新登录后的补执行限于计划时间后 24 小时内；投递及完成核验最长一小时。
- CLI 和 Codex 自身处理项目文件时仍可能需要文件夹权限。本机未撤销现有系统授权来做拒绝授权后的完整投递测试。

## English

- Add one-time scheduled messages to a selected existing Codex chat, with a per-message model and supported reasoning effort.
- Use user-level macOS LaunchAgents; do not create Codex automations or change global defaults or daily activation times.
- Bind picker entries directly to chat IDs and disambiguate duplicate titles.
- Route desktop-owned chats through their existing session, waiting for active work to finish; use CLI only when no desktop owner exists.
- Support larger status snapshots and verify the exact target and accepted turn completion. Never automatically retry uncertain attempts.
- Remove direct project-directory checks from desktop delivery; preflight and recheck CLI folder access, with distinct failure details.
- Default the date picker to now; add ±1 minute, ±10 minutes, ±1 hour and ±1 day buttons.
- Fix Command+V and support copy, cut, select all, undo and redo in the message editor.
- Parse negative exit statuses in background-service listings correctly.

### Install and Use

Apple Silicon and Intel archives with SHA-256; macOS 14+, Build 33. Hardened Runtime, ad-hoc signing, no Apple notarization. Desktop delivery depends on the installed Codex session interface. Message text remains in restricted local records until removed and is passed to Codex only for scheduled delivery. Missed triggers expire after 24 hours, with a one-hour delivery/completion limit. CLI and Codex project operations may still need folder permissions. Existing macOS permissions were not revoked for an end-to-end denial test.
