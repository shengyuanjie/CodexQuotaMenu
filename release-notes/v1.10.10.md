# v1.10.10 — Telegram 任务链接通知 / Telegram Chat-Link Notifications

## 中文

- 可为 Codex 用量配置独立 Telegram 机器人。新对话完成投递但未登记到默认“聊天”侧栏时，通知一次并提供“打开 Codex 对话”按钮。
- 设置窗口提供 Token、收件人绑定码和可选代理的分步说明，支持 Command+V；收件人可通过机器人私聊绑定自动识别。
- 定时计划先保存，再处理通知授权与后台读取检查。取消授权或检查失败不会撤销计划；任务仍按原定时间执行。
- 后台凭据读取失败只记录通知失败，不弹密码框、不重发任务或通知。
- 修复取消旧记录后“已移除”提示残留；保存后自动选中新计划，刷新保留选择。
- Token 仅保存在本机钥匙串。通知不含标题、正文、附件、输出或本地路径；请求使用固定 HTTPS 地址、拒绝重定向并隐藏原始错误。发布包审计新增 Telegram Token 格式及完整 ZIP 文件范围检查。

通知链接用于在运行任务的 Mac 上打开 Codex，当前仍不自动登记到默认“聊天”侧栏。历史记录不补发通知。

macOS 14+，Build 59。提供 Apple Silicon 和 Intel 安装包及 SHA-256 校验文件；Hardened Runtime 与 ad-hoc 签名，未经 Apple 公证。

## English

- Configure a dedicated Telegram bot. A completed new chat missing from Chats receives one notification with an Open Codex chat button.
- Guided token, recipient-code binding and optional proxy settings support Command+V.
- Save the delivery plan before optional notification authorization and background-read checks. Cancellation or failed checks never roll back the plan.
- Background credential failures do not prompt or resend the task/notification.
- Fix stale Removed feedback after deleting another record; select new plans automatically and preserve selection on refresh.
- Tokens stay in local Keychain. Notifications exclude titles, prompts, attachments, output and local paths. Fixed HTTPS requests reject redirects and sanitize raw errors. Release auditing now checks Telegram token syntax and the complete ZIP envelope.

Open links on the Mac that ran the chat. Automatic Chats registration remains unsupported; historical records are not backfilled.

macOS 14+, Build 59. Apple Silicon and Intel archives include SHA-256 files. Hardened Runtime and ad-hoc signing, without Apple notarization.
