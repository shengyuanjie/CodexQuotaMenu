# v1.10.9 — 定时对话投递与冲突恢复 / Scheduled Chat Delivery and Conflict Recovery

## 中文

- 定时新对话改由本机 app-server 创建并在同一交互会话发送，不再直接创建 `exec` 会话；核验回合完成后才标记投递成功。
- 分开显示回合完成和普通聊天侧栏登记状态；缺少登记时显示“已发送，侧栏未登记”，并提供“打开任务”。当前不自动补写 Codex 的侧栏登记。
- 创建后的任务 ID 在发送前保存；审批阻塞、失败、中断或可见性未通过时不自动重发。

- 已有对话遇到明确的发送前写入锁冲突时，最多等待 60 秒并重新发现桌面持有者；已有执行输出或结果不明时不自动重试，避免重复发送。
- “打开任务”只用于查看对话，不影响后台执行。

macOS 14+，Build 53。提供 Apple Silicon（arm64）和 Intel（x86_64）安装包及 SHA-256 校验文件，使用 Hardened Runtime 和 ad-hoc 签名，未经 Apple 公证。

## English

- Scheduled chat creation and delivery now share a native local app-server session instead of creating a noninteractive `exec` session. Delivery is marked successful only after the accepted turn completes.
- Separates delivery completion from desktop Chats registration. Unregistered chats show “Sent; not in Chats” and can be opened from their record. Automatic desktop Chats registration is not currently supported.
- Saves the chat ID before delivery and never automatically resends after an approval block, failure, interruption, or unverified visibility.

- Existing chats can recover from an explicit pre-submission writer-lock rejection by waiting up to 60 seconds and rediscovering the desktop owner. Execution output or an ambiguous outcome prevents automatic retries.
- Open chat is only for viewing the conversation; background execution does not require opening it.

macOS 14+, Build 53. Apple Silicon and Intel archives include SHA-256 files. Hardened Runtime with ad-hoc signing, without Apple notarization.
