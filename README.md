# Codex 用量菜单栏

[English](README.en.md) | 简体中文

一个原生 macOS 菜单栏工具，显示 Codex 剩余用量、重置倒计时、全局额外重置概率和当前正在执行的任务，并可向 iPhone Scriptable 锁屏小组件提供只读数据。

![应用图标](Resources/AppIcon-1024.png)

[下载最新版本](https://github.com/shengyuanjie/CodexQuotaMenu/releases/latest) · [完整使用说明](docs/product-and-usage.md) · [隐私说明](PRIVACY.md) · [支持项目](#支持项目)

## 产品功能

- 通过“默认模型…”选择新会话默认模型、推理强度及 1.5 倍速度（Fast）开关；实时读取可用选项，保存后回读核验，并识别系统层覆盖。
- 显示 Codex 当前剩余用量百分比、具体重置时间和倒计时。
- 下拉菜单显示官方账户接口返回的可用重置卡数量和到期时间；菜单栏和 iPhone 小组件不显示卡数。
- 同时展示 Codex 返回的各个用量窗口及当前方案类型。
- `▶` 显示当前仍处于活动状态的任务数量。
- `↻48h` 显示独立社区来源 `willcodexreset.com` 提供的未来48小时全局额外重置概率。
- 下拉菜单列出最近的活动任务，并明确显示异常任务。
- 每 5 秒自动刷新，也可随时手动刷新；查询暂时失败时保留上次成功结果。
- 公开预测每 5 分钟独立更新；应用最多读取响应的前 64 KiB，只保留摘要字段而不保留事件列表，可信缓存最多显示 2 小时。
- 预测首次达到或超过 50% 时显示鼓励提示；检测到两组用量已进入下一重置周期或新重置卡到账后恢复正常余量，概率先降到 50% 以下再重新越过阈值时才开始下一轮提示。
- 可选的手机只读接口默认关闭，使用 Keychain 令牌供 Scriptable 锁屏小组件在局域网或既有加密回家链路中读取。
- 菜单栏采用无前置图标的纯文字显示，减少视觉干扰。
- 支持跟随系统、简体中文和 English，并可在菜单中即时切换。
- 可将每日激活时间一键应用为本机后台激活，无需复制、粘贴或发送确认；应用只管理自己的用户级 LaunchAgent。
- 使用本机 Codex 登录状态，不要求用户向本项目提供账号令牌。
- 不含广告、遥测或第三方运行时依赖。

已完成任务不会计入菜单栏数字，也不会显示完成数量。

## 菜单栏显示

```text
Codex  晌90%余4时25分  周62%余2天  ▶1
```

| 显示内容 | 含义 |
|---|---|
| `晌90%余4时25分` | 5 小时用量窗口的剩余比例和重置倒计时 |
| `周62%余2天` | 每周用量窗口的剩余比例和重置倒计时 |
| `▶1` | 当前仍处于活动状态的任务数量 |

菜单栏标题不显示预测百分比：预测达到或超过 50% 且鼓励提示有效时，会显示 `Codex  晌81%余3时  周62%冲冲冲  ▶1`，保留短时余量和倒计时，并用“冲冲冲”替换每周倒计时；否则显示上述余量。点击菜单栏内容可查看 `↻48h 82%` 这类48小时预测、来源、最近任务标题、异常数量和更新时间。菜单中的“手机小组件”子菜单可启用只读接口并复制地址或访问令牌。

全局额外重置概率来自独立社区项目 `willcodexreset.com`，与 OpenAI 无隶属或官方认可关系，只表示不确定性估计，不是官方计划或发生保证。详情中的预测更新时间取自来源返回的 `data.updatedAt`，表示来源数据自身的更新时间；应用另行记录本机获取时间，用于判断缓存新鲜度。

应用不再判断任务是否正在等待用户操作，也不会分析回复文字来推断等待状态。Codex 仍标记为 active 的任务统一计入 `▶`；识别到完成标记后会从 `▶` 中移除。

## 系统要求

- macOS 14 或更高版本。
- 已安装并登录 Codex 桌面版、ChatGPT 桌面版内置 Codex，或 Codex CLI。
- GitHub Release 分别提供 Apple Silicon（`arm64`）和 Intel（`x86_64`）版本。

## 安装

1. 从 [GitHub Releases](https://github.com/shengyuanjie/CodexQuotaMenu/releases/latest) 下载与处理器匹配的 ZIP。
2. 对照 Release 中的 `.sha256` 文件校验下载内容。
3. 解压后将 `Codex用量.app` 拖入“应用程序”。
4. 因项目目前没有 Apple Developer 证书，应用采用 ad-hoc 签名且未经过 Apple 公证。首次启动可能被 Gatekeeper 阻止，可在 Finder 中右键应用并选择“打开”。

更新时仍可用 Finder 替换应用，替换后请打开一次新版本，让自动后台维护完成，无需命令行。

不要从不明转载站点下载安装包。公开发布包应由本仓库的 GitHub Actions 从对应标签自动构建。

## 使用说明

1. 从“应用程序”启动 `Codex用量.app`。应用没有主窗口或 Dock 图标，启动后请查看屏幕顶部菜单栏。
2. 直接读取剩余用量、重置倒计时和 `▶` 活动任务数量。
3. 点击菜单栏内容展开详情；选择“立即刷新”，或在菜单打开时按 `R`，可立即重新查询。
4. 选择“语言”，可在“跟随系统”“简体中文”和“English”之间即时切换。
5. 如需每日激活，选择“激活时间设置…”，添加每天需要的时间，然后点击“应用到 Codex”。应用会创建或更新对应的用户级 LaunchAgent，由官方 `codex exec --ephemeral` CLI 调用执行一次激活；不会新增可见的 Codex 任务对话记录。读取失败时才会显示“重试检测”。首次打开时列表为空；退出 CodexQuotaMenu 不影响已创建的后台任务。
6. 如需 iPhone 锁屏显示，按 [Scriptable 配置说明](mobile/README.md) 启用“手机小组件”只读接口。
7. 选择“退出”，或在菜单打开时按 `Q`，可停止应用及本机状态查询和手机接口。

受管 LaunchAgent 只使用完整标签 `com.local.codexquotamenu.activation.HHMM`，对应文件位于 `~/Library/LaunchAgents/`；共享前缀但不完整匹配的文件保持不变。时间列表为空时，“应用到 Codex”会移除本工具自己的 LaunchAgent。时间设置只有用户点击“应用到 Codex”时才会生效；更新应用后的启动检查会重新登记已有任务，保留原有时间。后台激活由应用的无界面入口执行，成功和失败保持静默。每个时间的最新摘要及每次运行的独立诊断记录保存在 `~/Library/Logs/CodexQuotaMenu/Activation/`，只记录执行时间、退出码、错误类别、使用百分比和前后窗口截止时间；原始命令输出仅在受限临时目录捕获，执行后清除。每次运行重新定位 CLI，校验结构化回合完成事件与两次查询的稳定截止时间，并要求额度使用非零。短暂失败或无法验证时最多重试一次，间隔15秒；认证或额度错误不立即重试。旧窗口在10分钟内到期时等待到期后5秒补试，否则记录旧窗口仍有效；“已同步”只表示配置与加载状态一致。Mac 从睡眠唤醒时，macOS 可能将错过的日历触发合并为一次补执行；应用不会自行追赶多次。 旧版 Codex 内置定时任务须在 Codex 中暂停；应用只检查本地状态并保留配置，不再自动删除旧任务文件，也不将文件移除视为调度已取消。

### 定时发送到指定任务

在菜单中打开“定时发送消息…”，从最近任务中选择目标（按任务 ID 绑定，同名任务显示 ID 尾部以区分），或粘贴完整任务 ID / `codex://threads/<ID>` 链接；再选择模型、该模型支持的推理强度、未来一年内的本机日期时间并填写消息。发送时间默认显示打开窗口时的当前时间；请调整为需要发送的未来时间。点击“安排发送”后，应用先只读核验目标任务，再创建独立的用户级 macOS LaunchAgent。每条消息只发送一次，不会创建 Codex 内置定时任务，也不会修改默认模型或已有的激活时间。可以在同一窗口查看 `pending`、`sending`、`sent`、`failed` 状态并移除记录；选中记录可查看目标任务 ID、模型、推理强度和失败原因。发送中的记录不能移除。

可点击“添加文件…”多选文件或照片，在附件列表中选择一项后点击“移除附件”。允许只发附件（自动使用“请查看附件。”作为消息）。最多20个附件，单个不超过25 MB，总计不超过100 MB；不支持文件夹或符号链接。点击“安排发送”时，附件副本保存到本条消息专属目录，之后移动、删除原文件不会影响发送。照片作为图片输入，HEIC、TIFF等格式转为JPEG副本；普通文件作为本地文件引用，由目标任务读取，仍受该任务的文件访问权限约束。发送前会检查副本完整性，附件不可用时整条消息失败，不会只发送部分内容。副本随记录保留，移除记录时一并删除。

定时消息存放在 `~/Library/Application Support/CodexQuotaMenu/ScheduledMessages/`，文件权限为 600；对应 plist 仅包含消息 ID，不含消息正文。安排消息时和到点执行时，应用均优先核验桌面端已有会话；桌面端持有任务时不直接检查项目目录。只有 CLI 路径才检查工作目录的读取与进入权限，权限不足或目录不存在会显示具体原因。元数据与模型查询从用户主目录启动，不继承项目目录。到点时应用先取得跨进程锁并原子记录 `sending`，再核对目标任务，桌面端持有该任务时，通过桌面端现有会话发送；若任务正在运行，会等待其空闲，投递与完成核验合计最长等待一小时。没有桌面端持有者时，才通过本机 Codex CLI 的 `exec resume --model` 发送。两种路径均使用这条消息保存的模型及推理强度；若到执行时所选模型已不支持该档位，会记为失败，不会静默换用其他档位。旧版未保存推理强度的记录仍沿用目标任务支持的档位或模型默认值。失败时仅保存脱敏的固定错误类别或退出码，不保存原始错误输出。桌面端路径核对目标任务及本次回合 ID，确认该回合完成后才记为 `sent`；CLI 路径要求正常退出、返回正确任务 ID 且包含 `turn.completed`。桌面端状态快照仅在进程内存中处理，接收上限为 128 MB，以支持包含较多工具历史的长任务；不会保存该快照。桌面端通信依赖本机 Codex 版本的会话接口；接口不兼容或连接中断时会记为失败，不会切换路径重复发送。执行被中断或结果不明确时不会自动重发，以免重复发送；用户可检查目标任务后再安排一条新消息。完成或失败后会卸载本条 LaunchAgent。Mac 睡眠唤醒或重新登录后的补执行只在计划时间后的 24 小时内允许，过期记为失败；到点之前的启动检查不会发送消息。本机时区变化可能影响 launchd 的触发时刻；跨时区旅行前请重新安排任务。应用退出后，已安排的 LaunchAgent 仍由 macOS 执行。

如需登录后自动启动，请打开“系统设置 → 通用 → 登录项”，点击“+”并选择“应用程序”中的 `Codex用量.app`。

应用会持续连接本机 Codex，并每 5 秒查询个人余量和任务；公开预测每 5 分钟独立更新。这里的“实时”是高频自动刷新，并非服务端推送。Scriptable 会建议 iOS 最早在 5 分钟后刷新，但系统不保证准时执行。

### 修改 Codex 默认模型

菜单栏 → **默认模型…**：从本机 Codex 后端读取可用模型及其支持的推理强度，显示实际的新会话默认值，以及“开启 1.5 倍速度（Fast）”复选框。开启保存 `service_tier = "fast"`，关闭保存 `service_tier = "default"`；若有系统速度覆盖，会同步更新并核验。不支持 Fast 的模型会禁用此选项，实际提速取决于模型与服务状态，可能增加用量消耗。点击“保存并核验”后，通过 `config/batchWrite` 更新用户默认配置，并重新启动独立查询进程进行回读核验；不会发起模型生成请求。

若 `/etc/codex/requirements.toml` 的 `[models.new_thread]` 覆盖了用户配置，应用会在必要时请求 macOS 管理员验证，只更新该表中的模型、推理强度及已有的速度覆盖，保留其他配置，并在同目录保存权限为 600 的唯一备份。密码由 macOS 验证，应用不接收或存储密码。配置来源不匹配、活动 profile 或不支持的 TOML 布局会明确报错，不覆盖未知托管策略。保存失败时可能已完成部分更新，应刷新检查实际值。

新默认值用于以后创建的本机 Codex 会话和下一次每日自动激活；现有会话保持原设置。每日激活在执行时读取实际默认模型、推理强度及速度设置（含系统托管覆盖），不固定模型版本；读取失败或默认模型已不可用时，记录 `default_model_unavailable`，不会回退到硬编码模型。升级前创建的调度可在“激活时间设置…”中点击“应用到 Codex”更新；旧版无界面激活入口的参数仍可识别，并在运行时使用当前默认值。保存并核验成功后，弹窗提供“现在重启 Codex”和“稍后手动重启”。立即重启会请求 Codex 正常退出，等退出后再重新打开；可能中断正在运行的任务。若 Codex 拒绝退出或退出超时，不强制结束进程，已保存的设置仍保留。`CodexQuotaMenu --check-default-model` 可只读检查后端默认值；`--model-settings` 可在启动时打开设置窗口。

## 隐私

应用会通过本机 Codex 进程查询用量和任务列表，并在本机读取 Codex 会话日志末尾最多 512KB，按结构化生命周期事件识别任务是否仍在活动、是否已经完成。会话内容只在内存中处理，不保存、不上传，也不包含遥测。

为同步和对账每日激活时间，应用日常只读取并验证 `~/Library/LaunchAgents/com.local.codexquotamenu.activation.HHMM.plist` 这类精确归属的文件，并通过 `launchctl` 检查对应用户级服务是否已加载。首次迁移旧版调度时，会在本机读取 `~/.codex/automations/*/automation.toml`，用于识别并安全迁移完整名称严格匹配 `CodexQuotaMenu · HH:mm` 的条目；不会读取这些自动化的运行对话，也不会修改其他 automation。写入前会暂存并验证完整目标配置；失败时尝试恢复本轮变更。应用不读取激活运行对话，也不上传调度配置；本地检测只能确认配置和加载状态，不能证明某次后台运行成功。 旧版 Codex 内置定时任务须在 Codex 中暂停；应用只检查本地状态并保留配置，不再自动删除旧任务文件，也不将文件移除视为调度已取消。

为显示公开预测，应用只请求 `https://willcodexreset.com/api/reset-radar`，不发送个人余量、任务、身份或 Codex 凭据。应用以 64 KiB 为上限读取响应前缀，只提取响应代码、未来48小时概率和来源更新时间，不保留或缓存 `events` 事件文本。摘要使用 `globalReset.willCodexResetForecast.v3` 键保存在 `UserDefaults`；手机接口开关及每条激活时间的小时、分钟、启用状态和稳定本地 ID 也保存在 `UserDefaults`，手机访问令牌保存在 macOS Keychain。手机接口默认关闭，响应只含汇总数值。

完整说明见 [PRIVACY.md](PRIVACY.md)。

## 安全边界

- 应用没有 App Sandbox，因为它需要启动本机 Codex 子进程并读取 Codex 会话日志。
- 发布构建启用 Hardened Runtime，但无 Apple Developer 证书时仍不会获得 Gatekeeper 信任。
- Codex 本身可能按其正常工作方式连接 OpenAI 服务；本应用另外只请求上述一个公开预测接口，不向其上传个人数据。
- 手机接口使用普通 HTTP 时只应位于可信局域网或用户已有的加密 VPN/回家链路中；不要映射端口到公网。
- 安全问题的报告方式见 [SECURITY.md](SECURITY.md)。

## 常见问题

- **启动后没有窗口**：这是菜单栏应用，请查看屏幕顶部；应用不会显示普通窗口或 Dock 图标。
- **一直显示“读取中…”或 `Codex --`**：确认 Codex 或 ChatGPT 桌面版已经安装并登录，然后选择“立即刷新”或重新启动本工具。
- **没有任务却显示 `▶ 1`**：先立即刷新；异常中断且长期不再更新的任务会在超过 30 分钟后停止计入运行中。
- **安装后提示无法验证开发者**：先确认安装包来自本项目 Release 且 SHA-256 校验通过，再在 Finder 中右键应用并选择“打开”。

更多排查方法和卸载步骤见 [产品功能与使用说明](docs/product-and-usage.md)。

卸载前若应用仍在，先在“激活时间设置…”中删除全部时间并点击“应用到 Codex”，确认显示“未配置”后再删除应用。若应用已经删除，只应逐项卸载并移除文件名和 plist 内 `Label` 都严格匹配 `com.local.codexquotamenu.activation.HHMM`（`HH` 为 `00`–`23`、`MM` 为 `00`–`59`）的 LaunchAgent；不要用前缀通配批量删除。安全的逐项检查与命令见上述完整说明。

## 从源码构建

需要 Xcode Command Line Tools：

```sh
./build-app.sh
```

构建脚本会：

1. 创建 Release 二进制；
2. 移除调试符号和编译机绝对路径；
3. 加入应用图标；
4. 启用 Hardened Runtime 并进行 ad-hoc 签名；
5. 验证包内签名。

如 Codex 安装在非标准位置，可在启动环境中设置 `CODEX_CLI_PATH`。

替换或重新签名应用后，首次启动会按主程序内容（不只版本号）检查已有激活任务，重新登记发生变化的后台任务，并验证程序能从 launchd 正常启动。检查不发送模型请求，保留已安装的时间设置，不自动应用设置窗口里尚未同步的修改；正在执行的激活任务不会被中断。核验成功后缓存指纹，同一程序再次启动无需重复登记。失败时设置窗口显示状态不可用，刷新可重试。

